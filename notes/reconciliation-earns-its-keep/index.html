The reconciliation layer earns its keep

A validation framework isn't a tax on a performance redesign — on the benchmark system, it's what made the aggressive part of the redesign possible.

  • validation
  • financial systems
  • reliability

There's a common instinct to treat a validation and reconciliation layer as overhead: something you bolt on after the real engineering is done, to satisfy a compliance checklist or catch the occasional edge case. On the fixed-income benchmark calculation redesign, it was closer to the opposite. The reconciliation framework is what made it possible to be aggressive with the performance work at all.

The reasoning is simple once you see it: if the only thing standing between a calculation bug and production is careful code review, you have to be conservative about how much you change at once. Every optimization is a new opportunity for a subtle numerical or logical error to slip through, and in a system whose output other financial software trusts directly, "subtle and wrong" is a much worse failure mode than "slow."

An independent reconciliation layer changes the calculus. It doesn't know or care how the calculation engine is implemented internally — it just checks whether the output is consistent with what's expected. That decoupling means the calculation engine is free to change dramatically, because there's a second, independent system watching for the class of error that matters most: correctness regressions that a human reviewer might miss.

In practice, that framework caught the kind of discrepancy that's easy to introduce during a large redesign and easy to miss in review — and it did that continuously, in production, not just at release time. The result was a system that could ship more aggressive latency improvements because the safety net existed, not despite the extra engineering effort it took to build it.

The general version of the lesson: if you want permission to change a system's internals significantly, invest in an independent way to verify its output first. The verification layer isn't the cautious option — it's what makes the ambitious option safe enough to ship.
